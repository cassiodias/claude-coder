# /invaders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `/invaders` command to puppet-coder that opens a focused pane with a playable Space Invaders. Claude's tool calls drop invaders or power-ups into the game.

**Architecture:** The game logic is pure functions in `hooks/arcade.ts`. A `Client` surface module, `hooks/invaders-client.tsx`, owns the loop (`surface.every(50)`), the keys (`surface.onKey`) and the game state (`setState`). `register.tsx` registers the command, opens the pane, draws the `Client`, and appends Claude's tool calls to a `$.state` list that reaches the `Client` as props.

**Tech Stack:** TypeScript/TSX Claude Code mod API (`claude-code`), tests through `claude plugin test` (`claude-code/testing`), type-check with `tsc -p .`.

**Spec:** `docs/superpowers/specs/2026-11-07-invaders-design.md`

## Global Constraints

- Tick: 50 ms. Grid: 3 rows × 6 columns of invaders. Lives: 3. Wave cleared → next wave marches faster.
- `tough` = 2 hits. `rapid` = 3 player shots on screen for 200 ticks. Otherwise 1 shot at a time.
- Keys: `left`/`right` or `a`/`d` move; space (`' '`) fires; `p` toggles pause; `r` restarts only on game over. Escape is the engine's (closes the pane).
- Minimum region 30 columns × 12 rows; below that draw `widen the pane to play` and pause.
- Tool → spawn kind: Edit/Write → `invader`, Bash → `tough`, Read → `rapid`, any other tool → nothing. Appended after `next(e)`, so only for calls that weren't denied.
- `invaders` state list capped at the last 20 entries; `n` strictly increasing; writes via `update`.
- The `Client` calls `setState` only from the `every` tick and `onKey`, never while rendering (the engine unmounts a render loop).
- Non-`Client` surfaces (`vscode`, `mobile`) draw exactly `/invaders needs the terminal or desktop app`.
- After every task, sync to the loaded copy: `rsync -a --exclude .git --exclude docs ./ /Users/cassiodias/.claude/dev-mods/77173cfd-8fd7-4cd1-b310-368837b315d5/puppet-coder/`

## Review Focus

1. **Key repeat bursts.** A held arrow sends about 30 events a second. The ship should move at most 2 cells per tick, not jump across the board. → Task 3 test `a burst of key repeats moves at most 2 cells per tick`.
2. **Space mashing.** It should never put more than 1 shot on screen (3 under `rapid`). → Task 2 test `fire is ignored while the shot limit is on screen`.
3. **A burst of tool calls.** More events than free top-row slots should never make an invader appear inside the formation or on the ship row. → Task 2 test `spawn is ignored when the top row is full`; Task 3 test `25 events in one prop update spawn at most the free slots`.
4. **Shrinking the pane mid-game.** It should pause without losing the score, and resume when it's widened again. → Task 3 test `shrinking below 30x12 pauses and widening resumes with score kept`.
5. **Reopening the pane.** It should start a fresh game that does not replay old tool calls. → Task 3 test `a new mount ignores events already in props`.

### Task 2: Game logic (`hooks/arcade.ts`)

**Files:**
- Create: `hooks/arcade.ts`
- Test: `tests/arcade.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type Input = { left: number; right: number; fire: boolean } // cells to move this tick (0..2), fire requested
  export type SpawnKind = 'invader' | 'tough' | 'rapid'
  export type Phase = 'playing' | 'paused' | 'over'
  export type Invader = { x: number; y: number; hp: 1 | 2 }
  export type Game = {
    columns: number; rows: number; shipX: number
    shots: { x: number; y: number }[]; bombs: { x: number; y: number }[]
    invaders: Invader[]; lives: number; score: number; wave: number
    tick: number; phase: Phase; rapidUntil: number; seed: number
  }
  export const SHIP_WIDTH = 2
  export function newGame(columns: number, rows: number, seed?: number): Game
  export function step(game: Game, input: Input): Game
  export function spawn(game: Game, kind: SpawnKind): Game
  export function togglePause(game: Game): Game
  export function cells(game: Game): string[] // exactly game.rows strings, each game.columns long
  ```
  Board geometry: row 0 is the top. The ship is on row `rows - 1`. The formation starts at row 1, invaders 2 cells wide with 1 cell gap. Points: 10 per hp-1 kill, 30 per tough kill. Glyphs in `cells`: invader `▞▚`, tough `█▙`, ship `▟▙`, shot `╻`, bomb `┇`, blank `' '`.

- [ ] **Step 1: Write the failing tests** in `tests/arcade.test.ts` (import `expect`, `test` from `claude-code/testing`):
  - `newGame(40, 16)` has 18 invaders, `lives === 3`, `score === 0`, `wave === 1`, `phase === 'playing'`.
  - `ship stops at the walls`: 100 steps of `{ left: 2, right: 0, fire: false }` → `shipX === 0`. 100 steps right → `shipX === 40 - SHIP_WIDTH`.
  - `a shot removes an invader and scores 10`: place the ship under an invader's x and step with fire until an invader is gone → 17 invaders, `score === 10`.
  - `fire is ignored while the shot limit is on screen`: 5 consecutive steps with `fire: true` → `shots.length === 1`. After `spawn(g, 'rapid')`, 5 steps → `shots.length <= 3` and `>= 2`.
  - `rapid expires after 200 ticks`: `spawn(g, 'rapid')` then 201 steps with no input → `tick > rapidUntil`.
  - `a bomb on the ship costs a life`: set `bombs: [{ x: shipX, y: rows - 2 }]`, then step → `lives === 2`.
  - `clearing the grid starts a faster wave 2`: set `invaders: []`, then step → `wave === 2` and 18 invaders. The number of ticks until the formation's x first changes is smaller in wave 2 than in wave 1.
  - `invaders reaching the ship row end the game`: set one invader at `y: rows - 1`, then step → `phase === 'over'`. Further steps leave the game unchanged.
  - `tough takes 2 hits`: `spawn(g, 'tough')` adds one invader with `hp: 2`. The first hit makes it `hp: 1` with score unchanged; the second removes it with `score === 30`.
  - `spawn fills the top-row edge slot`: after 3 kills from the top row, `spawn(g, 'invader')` puts an invader on the formation's top row in the free slot nearest an edge.
  - `spawn is ignored when the top row is full`: on a fresh game, `spawn(g, 'invader')` deep-equals `g`.
  - `togglePause`: `playing ↔ paused`. `step` on a paused game returns it unchanged. `togglePause` on `over` returns it unchanged.
  - `cells` returns `rows` strings of length `columns`, and the last row contains `▟▙`.
  - `same seed, same game`: two games from `newGame(40, 16, 7)` stepped 500 times with the same inputs deep-equal each other.

Step order inside `step`: move ship → move shots up and bombs down → resolve hits → march (sideways; at an edge, step down a row and reverse) → invader fire → clear/game-over checks → `tick + 1`. The march interval in ticks is `max(1, 12 - 2 * (wave - 1) - floor((18 - alive) / 3))`. Bombs: each tick, with probability `0.02 * wave` from a small LCG on `seed`, the lowest invader of a random column drops one bomb.

### Task 3: The `Client` (`hooks/invaders-client.tsx`)

**Files:**
- Create: `hooks/invaders-client.tsx`
- Test: `tests/invaders.test.tsx`

**Interfaces:**

- Produces: default export `ClientModule<{ claudeEvents: ClaudeEvent[] }>` where `export type ClaudeEvent = { n: number; kind: SpawnKind }` (exported from this file and re-used by `types/index.d.ts`). Its `Text` header reads exactly `score <n> · lives <n> · wave <n> · p pause`. On game over the header reads `game over · score <n> · r restart`.

Testing this module directly: a test may mount it through a `ui.render` hook that the test registers (`on('ui.render', { component: 'Pane', requestId: 'invaders' }, …)` returning `<Client key="game" module="../hooks/invaders-client.tsx" props={…} />`) before Task 4 exists. - [ ] **Step 1: Write the failing tests** in `tests/invaders.test.tsx`:
  - `right and space change the board`: read the ship row from `ui.find({ type: 'Text', text: /▟▙/ })`, then `ui.key({ key: 'right' })`, `ui.key({ key: ' ' })`, `ui.advance(50)`. The ship row text differs and some row contains `╻`.
  - `a burst of key repeats moves at most 2 cells per tick`: 10× `ui.key({ key: 'right' })`, then `advance(50)`. The ship's index in its row went up by at most 2.
  - `p pauses`: press `p` and `advance(500)`; the board is unchanged. Press `p` again and `advance(500)`; it changed.
  - `shrinking below 30x12 pauses and widening resumes with score kept`: after a kill (or set props so score > 0), `resize({ columns: 20, rows: 16 })` → finds `widen the pane to play`. `resize({ columns: 40, rows: 16 })` → header shows the same score and the board moves again after `advance`.
  - `new events in props spawn`: mount with `claudeEvents: []`, kill top-row invaders until a slot is free, redraw with `[{ n: 1, kind: 'invader' }]`, `advance(50)` → invader count up by 1.
  - `a new mount ignores events already in props`: mount with `[{ n: 1, kind: 'tough' }, { n: 2, kind: 'tough' }]` → no `█▙` on the board.
  - `25 events in one prop update spawn at most the free slots`: free 2 top-row slots, redraw with events n = 1…25 (sliced to the last 20) → invader count up by at most 2, and no invader on the ship row.
- [ ] **Step 2:** Run `claude plugin test .`. Expected: the new tests FAIL.
- [ ] **Step 3:** Implement the module:
  - Its state is `{ game: Game; lastN: number; pending: { left: number; right: number; fire: boolean }; tooSmall: boolean }`.
  - On first call (state undefined): `newGame(columns, rows - 1)` (one row for the header), `lastN` = max `n` in props or 0, start `every(50, …)` and `onKey(…)` once.
  - `onKey` adds to `pending` (`left`/`a` → left + 1, `right`/`d` → right + 1, `' '` → fire), toggles pause on `p`, and restarts on `r` only when `over`.
  - The tick clamps left/right to 2, calls `step`, applies `spawn` for each prop event with `n > lastN`, resets `pending`, and calls `setState`.
  - If `columns < 30 || rows < 12`, the tick sets `tooSmall` and pauses. When the size is back, it resumes only if it paused the game itself.
  - Rendering only reads state. Color glyphs with `Text` `color`: invaders `green`, tough `yellow`, ship `cyan`, bombs `red`.
  - If Task 1 found a click is needed, also draw `click to play` under the header until the first key arrives.
